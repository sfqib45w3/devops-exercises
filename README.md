# CI/CD Questions & Exercises

Questions and exercises related to Continuous Integration, Continuous Delivery, and Continuous Deployment.

## Questions

#### What is CI/CD?
* **Continuous Integration (CI)**: The practice of automating the integration of code changes from multiple contributors into a shared repository frequently. Automated builds and tests run to catch integration issues early.
* **Continuous Delivery (CD)**: Automatically building, testing, and preparing code changes for release to production. Deployment to production requires manual triggering/approval.
* **Continuous Deployment (CD)**: Automatically deploying every change that passes all pipeline stages directly to production without manual intervention.

#### What is the difference between Continuous Delivery and Continuous Deployment?
In Continuous Delivery, the deployment to production is manual (or triggered on demand), whereas in Continuous Deployment, every passing commit is automatically deployed to production.

#### What are artifacts in a CI/CD pipeline?
Artifacts are output files generated by pipeline steps—such as compiled binaries, Docker images, test reports, or deployment packages—that can be stored, passed between stages, or deployed.

#### What is pipeline as code?
Pipeline as code is the practice of defining deployment and build pipelines using code files (e.g., `Jenkinsfile`, `.gitlab-ci.yml`, `.github/workflows/main.yml`) stored alongside application source code in version control.

#### What is blue-green deployment?
A deployment strategy where two identical production environments (Blue and Green) exist. One serves live traffic while the other is updated. Traffic is then switched to the newly updated environment with zero downtime and fast rollback capabilities.
